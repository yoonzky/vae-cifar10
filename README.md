# vae-cifar10

Вариационный автоэнкодер на CIFAR-10 и проверка того, насколько сгенерированные им данные годятся для обучения классификатора.

[![Open in Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/yoonzky/vae-cifar10/blob/main/vae_cifar10.ipynb)

## Задача

1. Обучить VAE на CIFAR-10 без готовых реализаций автоэнкодера.
2. Построить "средний" объект каждого класса в латентном пространстве.
3. Добавить к нему шум и сгенерировать по 5000 новых объектов на класс.
4. Обучить свёрточную сеть на этих объектах, проверить на настоящих и сравнить с обучением на реальных данных.

## Как устроено

- **Энкодер** — четыре свёртки со stride 2 (3 -> 32 -> 64 -> 128 -> 256), BatchNorm и LeakyReLU(0,2), затем два линейных слоя на `mu` и `log_var`. Декодер зеркальный. Поверх `mu` стоит линейная голова на 10 классов. Классы `Encoder`, `Decoder`, `CNN` написаны вручную.
- **Loss:** MSE реконструкции и KL суммируются по картинке и усредняются по батчу, к ним добавляется кросс-энтропия головы с весом `GAMMA`.
- **Параметры:** латентное пространство 128, 60 эпох, learning rate 1e-3, batch 128, beta = 0,1, gamma = 100.
- **Генерация:** для каждого класса считаются среднее и ковариация латентных векторов его объектов. Новый объект получается как среднее плюс шум из нормального распределения с ковариацией этого класса.
- **Классификатор:** четыре блока Conv — BatchNorm — Conv — BatchNorm — MaxPool — Dropout, 25 эпох, batch 64. Каждая картинка приводится к нулевому среднему и единичному разбросу, при обучении случайно отражается и сдвигается до 4 пикселей.
- Сиды зафиксированы (`torch.manual_seed(37)`), устройство выбирается автоматически: CUDA, MPS или CPU.

## Результаты

Прогон на Mac M4 через MPS, 60 эпох VAE и по 25 эпох на каждую CNN:

| Обучающие данные | Точность на реальном тесте |
| --- | --- |
| Реальный CIFAR-10 | **84,08 %** |
| Сгенерированный VAE | **42,33 %** |

Точность на генерации заметно скачет от эпохи к эпохе: на последних десяти она была от 42 до 48 %, 42,33 % дала последняя эпоха. Разница с реальными данными 42 процентных пункта.

## Запуск

```
pip install -r requirements.txt
jupyter notebook vae_cifar10.ipynb
```

Данные качаются первой ячейкой сами, ключи и аккаунты не нужны. Основной источник — зеркало CIFAR-10 на Hugging Face (`uoft-cs/cifar10`, parquet на 114 МБ, разбирается в массивы за пару секунд), запасной — оригинальный архив с сайта Торонто. Во время загрузки печатаются проценты, файл кладётся в `./cifar10_data` и при следующем запуске берётся с диска. Если pyarrow или Pillow не установлены, ячейка ставит их сама. За прокси с подменой сертификата запрос повторяется без проверки.

Нужен GPU: в Colab это рантайм с T4, на Mac с Apple Silicon подхватывается MPS. На M4 весь ноутбук считается около 33 минут, на процессоре счёт идёт часами.
